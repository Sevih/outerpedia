## Lancement — message type (le numéro du lot en dernier mot, sans point final)

Un agent ne lit que ce fichier : les règles communes sont dans le préambule de
chaque prompt, la réponse attendue aussi. Message à coller tel quel, en
remplaçant le dernier mot :

```text
Ouvre /home/sevih/Documents/Projet perso/outerpedia/docs/lots-opus-2026-09-25.md et lis UNIQUEMENT la section du lot dont le code est le dernier mot de ce message (ne lis pas les autres lots). Fais tout ce que son bloc demande, préambule compris. Ta réponse finale tient en une seule ligne : Demande <lot> : commit hash <hash>. Lot à faire : B2
```

Réponse attendue : `Demande B2 : commit hash 1a2b3c4d`. Tout le reste (résumé,
vérifications, ce qui est laissé) est dans l'entrée DONE du commit, c'est là
que la relecture le lit. Un agent bloqué répond `Demande B2 : bloque — …` avec
sa question et sa recommandation en une phrase.

Cause, déjà établie : les liens internes sont sans préfixe de langue PAR CONSTRUCTION (en prod, le sous-domaine `fr.outerpedia.com` porte la langue et `src/proxy.ts` réécrit `/x` en `/fr/x`), et en mode `path` la fin de `proxy.ts` (« Domaine racine ») réécrit tout chemin sans préfixe vers `DEFAULT_LANG`. Ne change rien au mode sous-domaine.

```text
Objectif, dans `src/proxy.ts`, branche mode `path` uniquement (pas de sous-domaine détecté ET `LANG_ROUTING === 'path'` — importe-le de `@/lib/site` ; vérifie que le proxy peut lire cette constante, elle vient d'une variable `NEXT_PUBLIC_*`) : un cookie `lang` (SameSite=Lax, path=/, un an, pas HttpOnly n'est pas nécessaire mais pas interdit).
(1) Requête avec préfixe de langue valide non défaut (`/fr/...`) : laisse passer ET pose `lang=fr` sur la réponse.
(2) Requête sans préfixe, cookie `lang` valide et ≠ défaut : redirige 307 (temporaire, c'est un état utilisateur) vers `/<lang><pathname>` en conservant query et hash côté client (le hash ne traverse pas le serveur : rien à faire, le navigateur le garde sur une redirection).
(3) Requête `/en/...` (préfixe de la langue par défaut) : la 308 existante vers `/...` reste, mais la réponse EFFACE le cookie — c'est ce qui permet au `LanguageSwitcher` (`src/components/.../LanguageSwitcher.tsx`, branche « Mode path ») de revenir à l'anglais : modifie-le pour qu'en mode `path` la cible `DEFAULT_LANG` pousse `/en<stripped>` et non `<stripped>` (sinon la règle 2 renverrait vers la langue du cookie).
Les chemins exclus en tête du proxy (`/_next`, `/api`, `/images`…) restent exclus. Attention aux boucles : (2) ne doit jamais s'appliquer à un chemin déjà préfixé, ni à `/en/...`.

Tests : le proxy est une fonction pure de `NextRequest` → écris `src/proxy.test.ts` (vitest, `NextRequest` de `next/server` se construit avec une URL et des headers) couvrant les trois règles, le mode sous-domaine inchangé (hôte `fr.outerpedia.com`), et l'absence de boucle. Vérification manuelle décrite pour Sevih : sur `localhost:3000`, passer en fr, naviguer dans le menu, la langue tient ; revenir en en par le switcher, elle tient aussi.
```
