# Lots pour agents — mode d'emploi

> Comment déléguer un item du [TODO](./TODO.md) à un agent : un prompt complet
> par lot, écrit ici, lancé par le message type, relu avant d'être rangé. Ce
> fichier ne garde que l'outil ; un lot fait sort d'ici, sa trace est dans
> [DONE.md](./DONE.md) (66 lots du 25/09 au 05/10/2026, table des commits et
> leçons aux entrées du 04/10).
>
> Code d'un lot : A = une heure ou moins, B = une demi-journée, C = une
> journée, F = demande du jugement (agent Fable). Plusieurs lots tournent
> ensemble tant qu'ils ne touchent pas les mêmes fichiers ; ceux qui écrivent
> les six locales, les mêmes gros fichiers, ou qui lancent `datagen:build`
> passent un par un.

## Lancement — message type (le numéro du lot en dernier mot, sans point final)

Un agent ne lit que ce fichier : les règles communes sont dans le préambule de
chaque prompt, la réponse attendue aussi. Message à coller tel quel, en
remplaçant le dernier mot :

```text
Ouvre /home/sevih/Documents/Projet perso/outerpedia/docs/lots-opus-2026-09-25.md et lis UNIQUEMENT la section du lot dont le code est le dernier mot de ce message (ne lis pas les autres lots). Fais tout ce que son bloc demande, préambule compris. Ta réponse finale tient en une seule ligne : Demande <lot> : commit hash <hash>. Lot à faire : B2
```

Réponse attendue : `Demande B2 : commit hash 1a2b3c4d`. Tout le reste (résumé,
vérifications, ce qui est laissé) est dans l'entrée DONE du commit, c'est là
que la relecture le lit. Un agent bloqué répond `Demande B2 : bloque — …` avec
sa question et sa recommandation en une phrase.

Ce que fait l'onglet :

3. EMOJIS. Un bot ne bénéficie pas de la conversion du client Discord : `:scroll:` posté tel quel reste du texte. Une ligne seule de plus de 2 000 caractères : envoi refusé, dit clairement. Fonction pure, testée (sample de Sevih en fixture, cas limites à 1 999 / 2 000 / 2 001).
5. SALON. Une liste des salons du serveur où poster (texte et annonces, `GET /guilds/{id}/channels`, triés comme dans Discord, avec leur catégorie), le dernier choisi étant retenu (localStorage). Aucun salon par défaut au premier lancement : il faut en choisir un.
6. ENVOI. Un bouton « Envoyer », désactivé tant qu'il manque le jeton, le salon, du texte, ou qu'un emoji est inconnu ; une confirmation qui rappelle le salon et le nombre de messages. Les messages partent dans l'ordre, espacés d'une seconde, avec `allowed_mentions: { parse: [] }` (aucune mention ne notifie, même un `@everyone` tapé par mégarde) et, si la case « sans aperçu des liens » est cochée (cochée par défaut, retenue), le drapeau qui supprime les embeds. Un 429 est attendu puis retenté une fois (`retry_after`). Si un morceau échoue, on S'ARRÊTE : le journal dit lesquels sont partis, et un second clic ne reposte PAS ceux-là (reprise au morceau fautif). Journal NDJSON au fil, comme les autres gestes, avec le lien de chaque message posté. Ce geste ne committe et ne pousse RIEN.
7. CORRIGER APRÈS COUP. Après un envoi réussi, l'onglet garde (localStorage) le salon et les ids des messages postés, et propose « Mettre à jour le message posté » : mêmes morceaux, modifiés en place (`PATCH`). Si le nombre de morceaux a changé, il refuse et l'explique — pas de suppression ni de repost automatique. « Nouveau message » oublie ces ids.
8. CONFORT : le brouillon survit à un rechargement (localStorage) ; un bouton insère le gabarit de Sevih (ci-dessous) avec le lien de la note choisie ; rien d'autre.
